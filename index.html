C0400:52 → 01:06 14s

产品视频交付，不是只能做音响。

同一条需求给出两个切入版本：一个把参数翻译成场景，一个用产品本身的识别度抓人。交付时两个版本都在。

版本一 · 垂直场景切入
720×1280 · 15.07s
版本二 · 产品特写切入
720×1280 · 10.01s

怎么做的

先读产品资料，把参数和卖点分开；判断哪个参数最容易被一眼看懂，作为前 3 秒的钩子；按「钩子 → 产品 → 场景 → 行动」组织结构；生成素材、剪辑、检查字幕与产品事实；最后输出可直接发布的竖屏成片。

能力边界：这条视频是一个比较简单的应用场景，能证明可以快速理解产品并完成内容交付，不代表已经建成了完整的内容系统。真正有价值的是把一次制作变成长期、规模化的生产能力——那部分在上面两个系统里。
04
Method · 工作方法

先判断价值，再决定要不要上 Agent。

一个 Prompt 能解决的事情，不做复杂 Agent。只有涉及多步骤判断、知识来源、跨系统执行或数据反馈时，才提高系统复杂度。

C0501:06 → 01:20 14s
STEP 01
进入业务，梳理当前流程
先把现在怎么做的搞清楚，不急着上工具。
STEP 02
找出高频、重复、耗时、易错的环节
只在真正消耗人的地方动手。
STEP 03
选 Prompt / Skill / Agent / RAG / API / RPA
能用简单方案解决的，不上复杂系统。
STEP 04
先完成最小可用闭环
先跑通一次完整流程，再做扩展。
STEP 05
用效率、质量、成本、使用率验证
没被真正用起来的方案不算落地。
边界
做不到的，直接说做不到
没有长期负责过完整跨境电商数据系统——但方法、产品设计与把 MVP 做出来的执行能力可迁移。

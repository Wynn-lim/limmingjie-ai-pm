03 / DELIVERY

拿到产品资料，就能出成片。

参数理解 → 卖点取舍 → 结构设计 → 成片交付。同一条需求给出两个切入版本，方法可复制到任何标品品类。

版本一 · 垂直场景切入
720×1280 · 15.07s
版本二 · 产品特写切入
720×1280 · 10.01s

怎么做的

先读产品资料，把参数和卖点分开；判断哪个参数最容易被一眼看懂，作为前 3 秒的钩子；按「钩子 → 产品 → 场景 → 行动」组织结构；生成素材、剪辑、检查字幕与产品事实一致性；最后输出可直接发布的竖屏成片。

能力边界：产品视频是一个相对简单的应用场景，证明的是快速理解产品并完成内容交付的能力；真正有价值的是把一次制作变成长期、规模化的生产能力——那部分在上面两个系统里。
04 / METHOD

先判断价值，再决定要不要上 Agent。

一个 Prompt 能解决的事情，不做复杂 Agent。只有涉及多步骤判断、知识来源、跨系统执行或数据反馈时，才提高系统复杂度。

STEP 01
进入业务，梳理当前流程
先把现在怎么做的搞清楚，不急着上工具。
STEP 02
找高频、重复、耗时、易错的环节
只在真正消耗人的地方动手。
STEP 03
选 Prompt / Skill / Agent / RAG / API
能用简单方案解决的，不上复杂系统。
STEP 04
先完成最小可用闭环
先跑通一次完整流程，再做扩展。
STEP 05
用效率、质量、成本、使用率验证
没被真正用起来的方案不算落地。
Boundary · 能力边界
没有长期负责过完整跨境电商数据系统——但方法、产品设计与把 MVP 做出来的执行能力可迁移。AI 负责一致性（参数、品牌、字幕口播一致、违规表达），人负责判断（事实终审、创意选择、品牌调性、是否发布），这条边界在每个项目里都写清楚。

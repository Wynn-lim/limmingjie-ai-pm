02 / METHOD

先判断价值，再决定要不要上 Agent

一个 Prompt 能解决的事情，不做复杂 Agent。只有涉及多步骤判断、知识来源、跨系统执行或数据反馈时，才提高系统复杂度。

STEP 01
进入业务，梳理当前流程
先把现在怎么做的搞清楚，不急着上工具。
STEP 02
找出高频、重复、耗时、易错的环节
只在真正消耗人的地方动手。
STEP 03
选择 Prompt / Skill / Agent / RAG / API / RPA
能用简单方案解决的，不上复杂系统。
STEP 04
先完成最小可用闭环
先跑通一次完整流程，再做扩展。
STEP 05
用效率、质量、成本、使用率验证
没被真正用起来的方案不算落地。

10 / ONBOARD

加入公司后能做什么：四个项目

围绕耳机音响类 3C 业务，先做能跑通、能被业务真正用起来的四个项目。

PROJECT A
3C 产品内容自动化生产线
问题：同一款耳机或音响要在多个平台产出多个版本的内容，资料分散、参数容易写错、制作周期长。
方案：统一产品资料，用三个核心 Skill 生成多场景、多平台、多语言的脚本与视频，并保留人工终审。
制作时间返修率素材数量点击率转化率
PROJECT B
店铺数据自动周报与经营看板
问题：店铺、广告与库存数据分散在不同后台，靠人工导表汇总，口径不一致且滞后。
方案：确认数据源，优先走 API；没有 API 时评估 RPA 或定时导出；统一口径后输出周报与异常建议。
汇总耗时口径一致率异常发现时效周报使用率
PROJECT C
评论、售后与用户反馈分析 Agent
问题：评论、客服记录和退款原因分散，产品问题与表达问题混在一起，很难分头改进。
方案：汇总多来源反馈，按型号和问题分类，区分产品问题、表达问题、物流问题与用户误解，分别反馈对应部门。
处理条数分类准确率问题闭环率同类问题复现率
PROJECT D
产品知识库与 GEO 内容资产
问题：产品参数、卖点、FAQ 分散在各处，对外表述不统一，也不容易被搜索与理解。
方案：为每个 SKU 建立带来源和更新时间的知识卡，统一参数、卖点、FAQ 与禁用表达，并围绕真实用户问题生产结构化内容。
知识卡覆盖率信息一致率内容引用情况监测频次

GEO 目标：提高品牌信息被搜索、理解和引用的概率，并建立持续监测机制。不承诺必然被大模型推荐。公司具体使用的跨境销售平台以入职后确认，方案按「API 优先、无 API 时评估 RPA 或定时导出」的通用条件设计。
